Getting Started

Up and running in minutes

Follow these steps to deploy your own Griphook instance.

Private Deployment Only

Do not expose GRIPHOOK to the public internet. This system executes shell commands on your servers and should only be deployed in a private, secured environment accessible to you and authorized personnel only.

For secure remote access, use a zero-trust tunnel solution:

Cloudflare Zero Trust Twingate Tailscale

Prerequisite — install Docker

Griphook ships as Docker images, so Docker is the only host dependency. Linux has native Docker support; macOS and Windows run it through Docker Desktop. Click through to the official Docker docs for your platform, then come back here to bring up the stack.

Linux

Native support
apt dnf pacman zypper
1 Install Docker Engine Recommended
~2 min ~150 MB

Linux has native Docker support. The official docs cover every distro (apt, dnf, pacman, zypper) and include the convenience script. You get the Docker Engine, CLI, and Compose plugin — no Desktop GUI needed.

sudo or root curl
docs.docker.com/engine/install/ Open →
After install, add yourself to the docker group (then log out & back in): sudo usermod -aG docker $USER Verify with docker compose version — you need the Compose plugin (v2) for the stack below.
2 Post-install & rootless Optional

Recommended hardening. The post-install guide covers running Docker as a non-root user, configuring log rotation, and the rootless daemon mode. Worth skimming before running Griphook long-term.

docs.docker.com/engine/install/linux-postinstall/ Open →

macOS

Homebrew Docker Desktop macOS 12+
1 Install Docker Desktop Easiest
~3 min ~700 MB

macOS runs Docker through Desktop. The official guide walks through the .dmg installer (or brew install --cask docker). Works on every Apple Silicon and Intel Mac. Launch it once — the daemon auto-starts on login after.

macOS 12+ (Monterey) Apple Silicon or Intel
docs.docker.com/desktop/install/mac-install/ Open →
Wait for the whale icon in the menu bar to stop animating, then verify: docker compose version Note: Docker Desktop on macOS uses a Linux VM under the hood — Griphook containers see host.docker.internal as your Mac for Ollama access.

Tune the VM before running the stack. Default Desktop limits (2 GB RAM, 2 CPU) are too low for Postgres + agent + UI. Bump to at least 4 GB RAM and 2 CPUs in Settings → Resources.

docs.docker.com/desktop/settings/mac/ Open →

~5 min ~1 GB

Windows runs Docker inside WSL 2. Open PowerShell as Administrator and run wsl --install, then reboot. This installs the default Ubuntu distro. The official guide covers manual steps, distro selection, and troubleshooting.

~4 min ~900 MB

The .env file — every variable

Griphook is configured through a single .env file next to your Compose file. Copy .env.example to .env and edit the values. Only AGENT_TOKEN is required; everything else has sensible defaults or can be set later from the UI's Settings page.

AGENT_TOKEN Required. Secret token for API auth and the setup wizard. Use 32+ random chars in production. Default: 1234 (dev only).
AGENT_ADK_PROVIDER AI backend: gemini or ollama. Optional — default is ollama. Switch anytime from Settings → AI Configuration with no restart.
AGENT_ADK_MODEL Model name for the chosen provider. Gemini: gemini-2.0-flash. Ollama: any tool-capable model you've pulled (llama3.1:8b, qwen3, etc.).
GOOGLE_AI_API_KEY Free Gemini key from aistudio.google.com/apikey. Only needed when AGENT_ADK_PROVIDER=gemini.
OLLAMA_BASE_URL URL of your Ollama server. Default http://127.0.0.1:11434. From inside a container, use http://host.docker.internal:11434 or a shared network.
OLLAMA_MODEL Ollama model tag. Must support tool-calling. Pull with ollama pull <model> first.
AGENT_WORKING_DIR Where the agent runs shell commands. Default /tmp. Mounted into the agent container.
AGENT_DEFAULT_SHELL Shell used for executions. Default /bin/sh. Set /bin/bash if your image has it.
AGENT_MAX_CONCURRENT Max parallel executions per agent. Default 5.
SLACK_* Optional Slack skill: SLACK_APP_TOKEN, SLACK_BOT_TOKEN, SLACK_WEBHOOK_URL, SLACK_DEFAULT_CHANNEL, SLACK_SLASH_COMMAND.
GMAIL_* / SMTP_* Optional email skills. Gmail SMTP uses GMAIL_EMAIL + GMAIL_APP_PASSWORD. Generic SMTP uses SMTP_HOST, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD.
FLIRT_* Optional Wingman skill: FLIRT_USER_NAME, FLIRT_STYLE, FLIRT_INTERESTED_IN, FLIRT_PERSONALITY.
.env 
# === Required ===
AGENT_TOKEN=change-me-to-a-long-random-string

# === AI provider (optional — defaults to ollama) ===
AGENT_ADK_PROVIDER=ollama
AGENT_ADK_MODEL=llama3.1:8b
OLLAMA_BASE_URL=http://host.docker.internal:11434
OLLAMA_MODEL=llama3.1:8b
# Or, for Gemini:
# AGENT_ADK_PROVIDER=gemini
# AGENT_ADK_MODEL=gemini-2.0-flash
# GOOGLE_AI_API_KEY=AIza...

# === Agent runtime ===

AGENT_DEFAULT_SHELL=/bin/sh
AGENT_MAX_CONCURRENT=5

# === Skills (all optional) ===

The Compose file — full stack

This single docker-compose.yml brings up Postgres, the agent, and the UI — all on one shared network so the UI can reach the agent by its service name. Save it next to your .env and run docker compose up -d.

docker-compose.yml 
# docker-compose.yml — Griphook full stack (Postgres + agent + UI)
services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: runner
      POSTGRES_USER: runner
      POSTGRES_PASSWORD: runner
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U runner -d runner"]
      interval: 10s
      retries: 5
    networks:
      - runner-agent-net

  agent:
    image: nullruntimedev/griphook-agent:latest
    restart: unless-stopped
    ports:
      - "8090:8090"
    env_file: .env
    environment:
      SERVER_PORT: "8090"
      SPRING_PROFILES_ACTIVE: production
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/runner
      SPRING_DATASOURCE_USERNAME: runner
      SPRING_DATASOURCE_PASSWORD: runner
      JAVA_OPTS: "-XX:MaxRAMPercentage=75.0 -XX:+UseG1GC"
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - runner-agent-net

  ui:
    image: nullruntimedev/griphook-ui:latest
    restart: unless-stopped
    ports:
      - "3000:3000"
    volumes:
      - ui-data:/app/data
    environment:
      NODE_ENV: production
    depends_on:
      agent:
        condition: service_healthy
    networks:
      - runner-agent-net

networks:
  runner-agent-net:
    driver: bridge

volumes:
  postgres-data:
  ui-data:

The agent reads all AGENT_*, OLLAMA_*, GOOGLE_AI_API_KEY, and skill vars from env_file: .env. The hardcoded Postgres credentials are for local dev — change them for any non-isolated deployment.

Running multiple agents

Griphook is built for multi-agent. The UI is a control plane — one UI can manage many agents. Add more agent-N services to the Compose file, each on the same network, and register each one in the UI's Manage Agents → Add form using its service name as the host.

docker-compose.yml — two agents 
# ... postgres service unchanged ...

  agent-1:
    image: nullruntimedev/griphook-agent:latest
    restart: unless-stopped
    ports:
      - "8090:8090"
    env_file: .env
    environment:
      SERVER_PORT: "8090"
      SPRING_PROFILES_ACTIVE: production
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/runner
      SPRING_DATASOURCE_USERNAME: runner
      SPRING_DATASOURCE_PASSWORD: runner
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - runner-agent-net

  agent-2:
    image: nullruntimedev/griphook-agent:latest
    restart: unless-stopped
    ports:
      - "8091:8090"
    env_file: .env
    environment:
      SERVER_PORT: "8090"
      SPRING_PROFILES_ACTIVE: production
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/runner
      SPRING_DATASOURCE_USERNAME: runner
      SPRING_DATASOURCE_PASSWORD: runner
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - runner-agent-net

  ui:
    image: nullruntimedev/griphook-ui:latest
    restart: unless-stopped
    ports:
      - "3000:3000"
    volumes:

    environment:
      NODE_ENV: production
    depends_on:
      agent-1:
        condition: service_healthy
    networks:
      - runner-agent-net

How to connect each agent in the UI

  1. 1 Open the dashboard at http://localhost:3000. The setup wizard appears on first launch.
  2. 2 In the wizard (or later via Manage Agents → Add), enter the agent URL as http://agent-1:8090 — the service name resolves on the shared runner-agent-net network. Use http://localhost:8090 only if the UI runs on the host.
  3. 3 Paste the AGENT_TOKEN from your .env. Both agents share the same token by default; give each a different token by using a per-service environment override if you want separate auth.
  4. 4 Repeat for http://agent-2:8090. The UI now shows both agents in the sidebar — switch between them, or fan out a chat to a specific one. All agents share the Postgres DB for history.

Note on ports: only the first agent maps 8090:8090 on the host. The second maps 8091:8090 — the container port is the same, the host port differs. Inside the network both are reached on 8090 by their service name. Add as many agents as you need; each gets its own ports entry and service name.

# From the folder containing docker-compose.yml and .env docker compose up -d # Check the stack is healthy docker compose ps # Expected: postgres, agent, ui all "Up (healthy)"
# Tail all services docker compose logs -f # Just the agent docker compose logs -f agent # Just the UI docker compose logs -f ui
# Stop and remove containers (keeps data) docker compose down # Wipe the Postgres data volume too (fresh start) docker compose down -v
# Check if the agent is running curl http://localhost:8090/health # Response: { "status": "ok", "version": "0.1.0" }
# Execute deployment commands curl -X POST http://localhost:8090/execute \ -H "Authorization: Bearer $AGENT_TOKEN" \ -H "Content-Type: application/json" \ -d '{ "name": "Deploy v1.0", "steps": [ { "name": "Pull", "run": "docker pull app" }, { "name": "Start", "run": "docker run -d app" } ] }'
# Chat with the AI agent curl -X POST http://localhost:8090/agent/chat \ -H "Authorization: Bearer $AGENT_TOKEN" \ -H "Content-Type: application/json" \ -d '{ "message": "Deploy the latest version and notify Slack" }' # The AI understands natural language!
